## Maintain HOW_IT_WORKS.md

Treat the project-root `HOW_IT_WORKS.md` as a living product document for a nontechnical product owner.

Refresh the document after changes to core flows, agent behavior, architecture, module responsibilities, or user-visible behavior.
Agent behavior includes loops, tool use, plans, memory, and cooperation between agents.
A relevant code change is incomplete until the document reflects the current behavior.

- Describe the current system. Do not write a change history.
- Update each relevant Mermaid diagram.
- Explain each important new concept in plain language with a short analogy.
- Separate code implementation, local tests, real operation, and user acceptance.
- State the evidence for each completion claim and the current limits.
- Do not treat code, a mock, or a successful build as proof of real-channel acceptance.
- Update the last-reviewed date at the bottom of the document.
- Give the product owner a summary of the document update in 2–3 sentences.

Keep project facts in this project's `HOW_IT_WORKS.md`. Do not copy them into global instructions.
