## 维护 HOW_IT_WORKS.md

把项目根目录的 `HOW_IT_WORKS.md` 作为给非技术产品负责人阅读的活文档。

修改核心流程、Agent 行为、系统架构、模块职责或用户可感知的行为后，必须同步更新该文档。
Agent 行为包括循环、工具调用、规划、记忆和多 Agent 协作。
相关代码改动完成后，如果文档没有反映当前行为，任务不能视为完整交付。

- 只描述当前系统，不写变更历史。
- 同步更新相关的 Mermaid 图。
- 用通俗语言解释每个重要的新概念，并补充一个简短类比。
- 明确区分代码实现、本地测试、真实运行和用户验收。
- 根据证据描述完成度，并说明当前限制。
- 不能把代码存在、模拟结果或构建成功写成真实渠道已经通过。
- 更新文档底部的最后核对日期。
- 用 2–3 句话告诉产品负责人这次文档改了什么。

项目事实只保存在本项目的 `HOW_IT_WORKS.md` 中，不复制到全局指令。
